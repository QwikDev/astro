# Consolidated Review

## High
- File path: `apps/website/src/layouts/docs/DocsLayout.astro`; line: `91`; severity: `high`; category: `Diff`; description: The new docs search logic uses a TypeScript annotation inside a plain `script is:inline` block (`loaded.map((r: any) => ...)`). `pnpm -C apps/website astro check` fails with `ts(8010): Type annotations can only be used in TypeScript files`, so the website package no longer passes Astro's type check. Suggested fix: Remove the inline type annotation, or move the search code into a typed client module and import it from the page.
- File path: `libs/qwikdev-astro/src/index.ts`; line: `93`; severity: `high`; category: `Diff`; description: Removing the Vite `resolve.noExternal` safeguard regresses supported build modes for the integration. `pnpm playwright test --project static --project preview --project node` now fails in the `static` and `preview` projects with `TypeError: Invalid module "@qwik-client-manifest" is not a valid package name...`, while `node` still passes, which points directly at the changed bundling behavior in this config block. Suggested fix: Restore an equivalent `resolve.noExternal` rule for `@qwik.dev/core` and `@qwik-client-manifest`, then keep static and preview fixture coverage in CI as a regression check.

## Low
- File path: `apps/website/src/layouts/docs/DocsLayout.astro`; line: `90`; severity: `low`; category: `Diff`; description: Search results are rendered through `resultsList.innerHTML` with interpolated values from both Pagefind (`r.url`, `r.meta?.title`, `r.excerpt`) and the raw query string (`q`). That bypasses Astro/Qwik escaping guarantees and turns the search UI into a DOM injection sink if unexpected HTML reaches those values. Suggested fix: Build result nodes with `createElement` and `textContent`, or escape/sanitize every interpolated value before inserting it into the page.
